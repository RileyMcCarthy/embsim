# Plan: every component a node

## 1. The model

Every fitted part contributes to the one quasi-static nodal solve that already exists (`board/src/cluster.rs` `QuasiStaticMna`: Norton-stamped Thevenin sources, dense elimination; R1, R16). Resistors, closed switch poles and on-state channels are conductances; rails are declared terminals — a source referenced to the regulator's own ground pin, entering every dependent solve as a constant; pads are Thevenin sources at the device's real strength; diodes, LEDs, BJTs, FETs and the CCR are piecewise-linear elements whose region is chosen by a bounded, ordered flip loop inside one solve, cold-started every time; capacitors are single-pole closed forms. A solve runs only when an input to a cluster changes and yields the operating point at that instant. Time enters in exactly one way: a node with capacitance publishes `Settling { v0, v_inf, tau, t0_ns, level }`, analog senses evaluate v(now) at read time, and the instants at which a digital sense would flip and at which the exponential is within one quantum of v∞ are computed in closed form and armed on the wheel as integer nanoseconds. Nothing is integrated per tick (R8, R11). Deliberately not SPICE: no timestep, no Newton on exponential laws, no inductor dynamics (L stays a DC short), no multi-pole transients (one pole per resistive block, stated), no ground the harness did not declare (R18), no parasitics the netlist or scenario does not name. The `ClusterSolver` seam remains the escape hatch (R21); the decision record's revisit trigger is not pulled.

One more rule, from the user, that shapes everything below: **there is one pipeline** — netlist part → registry class → node. No stub tier, no facade-only part, no allow-list. A part is a node whose class has behaviour, or the board refuses to build naming the part and its value. §3 says what that deletes.

### Three rules the taxonomy rests on

**1. Terminals are declared, and they are cluster boundaries.** A terminal is a root held by a *declared* source — a `PowerOut` pin, a harness `power(V)` endpoint, a `net_stuck` — never a root inferred from a drive's impedance (`PinHandle::set_drive` accepts any impedance per call, `component.rs:386-400`, so an impedance-keyed boundary would flip mid-run while membership is fixed at build). Each terminal is its own one-node cluster whose state is assigned once (two disagreeing terminal sources on it → Contention, once, not per dependent), and `build_topology` records a `terminal → dependent clusters` fan-out that `set_drive`/`dirty_scope` consult when a rail changes — so `resolve_dirty == full pass` survives, and the incremental-vs-full property test (`engine.rs:4877-4926`) gains random terminal drive changes as phase 4's first commit. Edges and caps touch a terminal, nothing unions through it, its voltage enters the solve as a constant. This is Dirichlet elimination for terminals, which `cluster.rs:52-64` rejected for *all* ideal sources; the revision is stated there: it is safe because a terminal's own contention is decided before any dependent solve runs, and it is gated on `nominal_analog_cluster` and `net_stuck_shared_node` passing at 1 µV without re-blessing. What the rule prevents: with D/LED as edges and no boundary, `mad_edge.net` collapses +3.3V, +5V, GND and all 21 LED chains into one **47-net** cluster — the chains are inverter Y → 220 Ω → anode → cathode on GND, so it is GND that grows — and any Analog sense in it force-escalates every P-pin edge (`engine.rs:1191-1197`).

**2. Source-strength projection, in one form.** Today two driving slots on one root with different levels are Contention regardless of impedance (`levels_of`, `engine.rs:1017-1029`, `:1219-1224`), so a P2 pad publishing `{3.3 V, 15 kΩ}` against any sink is Contention. The replacement ranks every source reaching a root by **total ohms** = slot impedance + series path from the cached `dist` matrix (a terminal: path only). A source with total ≥ `WEAK_DRIVE_OHMS = STREAM_COLLAPSE_THRESHOLD` (1 kΩ) is a *pull* and never contends. Among the rest: a source ≥ `ESCALATION_IMPEDANCE_RATIO` (10×) the strongest loses — the state is the strongest's, and because it lost through less than 1 kΩ it is a fight, so `Finding::Contention` names both (the flash-vs-card case on P58: the card reaches through 25 + 240 = 265 Ω ≥ 250, node ≈ 3.0 V, reads the flash's level, finding raised — the draft's "Contention" was wrong and the reviewer right). Disagreeing sources within 10× **solve** (m ≤ 2 in every case on these boards), publish the divided voltage, and project it through the dead band `V_IL/V_IH = 0.8/2.0 V` (JESD8C.01, the 3.3 V LVCMOS standard — JESD8-7A is the 1.8 V one; a net-level constant until a PinDecl carries its own): inside the band → Contention + `AmbiguousLevel`; outside → Analog(v) + `Finding::Contention`. Two 25 Ω push-pulls still sit at 1.65 V, inside the band, so every existing Contention holds; a driver against a terminal on its own root stays Analog(rail) as today (the firmware must *see* a short-to-rail, not hold its last level) and gains the finding it lacks. Otherwise the winner sets the state: a strong slot on the root → `Driven(level)`; a terminal on the root → `Analog(v)` (`an_injected_short_outvotes_a_driver_reached_through_resistance` keeps its precedence); anything else → `Pulled(level, ohms)` where ohms is the winner's series path, and a *weak* slot's own impedance is part of that path — a 15 kΩ pad is a resistor to its rail, a 25 Ω pad is a driver. So the 47 Ω single edge stays `Pulled(_, 47)` bit-identical (`a_driven_level_crosses_a_series_resistor`, `engine.rs:3672-3706`), the lone I2C pad reads `Pulled(High, 15000)`, and the unstuck-GND chain reports the path that wins, not 82 200. Escalation trigger 2 (`engine.rs:1186-1197`, both levels present anywhere in the cluster) retires in favour of this ranking.

**3. Membership is fixed at build; the only mutable conductance is the plant's.** Switch poles and jumpers are build-time identity unions (rule above). The one runtime-mutable edge is the bridge leg the plant sets through `Command::SetEdge { edge, ohms }` — value-only, never a `topology_version` bump, refreshing that cluster's `dist` locally — and it lands in phase 7 with its first real consumer. The invariant that wins is "clusters are electrically independent, dirty scope is exact" (`engine.rs:949-958`); there is no epoch machinery and `subscribe_topology` (`engine.rs:2915-2920`) stays the deferred seam it is.

## 3. One pipeline

A netlist part is **either** a node whose class has behaviour **or** the board refuses to build with `RegistryError::UnknownPart { reference, part, value }` (the error gains `value` — on the transcribed EC32 netlist `part` is empty and the message would name nothing). The pipeline is `classify()` → `PartClass` → node; the classes are exactly the taxonomy rows: `Passive`, `Switch`, `Pwl`, `Boundary`, `Probe`, `Mechanical`, `Registered` (a model constructor: `Rail`, `Oscillator`, `LogicGate`, `Supervisor`, `Opto`, `Psram`, `P2Package`, and the models that exist). A connector is a pass-through node, a test point a probe node, a mounting hole or board outline an explicit `Mechanical` node, an IC nobody has modelled a build error. There is no allow-list and no "declare its outputs as inputs so it cannot contend" rule.

## 6. Cost model

Solves per event are unchanged: one `resolve_dirty` of the touched cluster per applied drive (`engine.rs:2291-2361`), on the fast path unless two sources within 10× disagree (an m ≤ 2 solve) or an Analog sense is present. Additions are bounded per cluster: rule 2 is an O(sources) ranking per dirty root from cached `dist`; PWL adds ≤ 2N solves only in a dirty cluster containing elements (cold start makes that the bound every time, and at m ≤ 8 it is ~170 multiply-adds per solve); a settle adds one `ln_q` per capacitive node and at most two wheel entries; there is no R_th solve on the fast path. Rails add no solves of their own — terminals are constants — and a rail change costs one fan-out walk; a rail whose feedback divider hangs between its output and its ground solves that divider's two-root cluster once when the rail rises (rule 2: two comparable sources, the rail through R_top and ground through R_bot), which is the ROM boot's two at t_SS (phase 4).

Cluster size is the decision. Rule 1 keeps every pull-up a 2-node cluster and every LED chain {Y, anode} plus terminals; identity unions keep S301 at zero cost; today's largest clusters (EC32 8 nets across GND/Common_VDD/LDOin, Edge 11 across +3.3V/LED anodes — offline sizing) split at their rails. Decoupling caps contribute nothing. Expected max m ≤ 8 on all three boards; phase 0 measures, phase 4 bounds (phase 3 measured 29 / 10 bare and 20 on the Edge `+3.3V` cluster under the rails — the resistor edges' unions through terminals, phase 4's to cut; see the phase-3 review record). On the ROM boot every SPI edge is a 25 Ω pad against 10.5 kΩ to a VIO terminal (10 500 ≥ 1 kΩ: a pull), so no matrix is built today and none after; the projection gains one compare per source pair. Expect the 16.9 k edges within noise of 0.2 s (≈12 µs/edge wall, dominated by QEMU slices and wakes, not the engine). LU caching waits for phase 7 and is dropped if the bench does not justify it. Event ceilings (`isolation_bridge` 32, `pulse_bridge` 64) are rate-independent and untouched because STEP stays a rate.

## 7. Determinism

The crossing is Δ = τ·ln((v∞ − v0)/(v∞ − v_th)), defined only when v_th lies strictly between v0 and v∞ (the (v0 − v_th)/(v∞ − v_th) form in the findings is ln of a negative for a 0→3.3 V step); the settle end is Δ_end = τ·ln(|v∞ − v0| / 1 µV). The log is **embsim's own** `ln_q`: fixed-point over the already-quantized 1 µV / 1 mΩ inputs (table + integer Newton, stated max error 1e-9 relative, no libm) — a reviewer is right that a platform `ln` inside an event instant is the first place a cross-OS ULP would change event *order* rather than a logged value, and the goldens are blessed on macOS and compared on the ubuntu-only leg (`ci.yml:60-66`). τ stays f64 from the quantized R_th and C (no τ_ns rounding: 25 Ω·100 pF is 2.5 ns, not 2 or 3); Δ is computed in f64 from `ln_q`'s result and rounded exactly once: t = t0 + round(Δ_ns). A Δ that rounds to 0 is **not scheduled** (round, not ceil), and the settle-end entry is armed only for nodes with an Analog sense — which is why a pad-scale RC on a 25 Ω driver into 10 pF leaves the bit grid untouched on every SPI edge. `Settling` is published only when the crossing rounds to ≥ 1 ns or an Analog sense exists; otherwise the DC projection is published at once. At t_cross the engine republishes with `level` flipped — a different tuple, so `same_state` delivers; at t_end it republishes the DC projection. `level_of(Settling)` is its `level` field (existing consumers stay correct; a reviewer is right that the draft's "evaluate at read time" could not deliver under `same_state`); `volts_at` is for RC-aware analog consumers. A capacitive node whose every source is released publishes `Analog(v0)` held (memory, no entries, no invented value). Same binary + same inputs → same bits (R12d); the macOS leg joins the determinism job for any fixture that carries a `Crossing` record before phase 5 blesses one. Every armed instant carries the cluster's solve generation and a wheel seq; it fires in (deadline, seq) order after same-instant drives (R11); a drive on a settling cluster re-solves with v0 = v(now), bumps the generation, and the stale entry is dropped on fire. PWL flips are one-at-a-time in declaration order from a cold start, bound 2N, so a pass is a function of (topology, drive table, t) alone — warm-starting from the previous solve made two histories reaching one drive table publish different states and broke `resolve_reference`; on exhaustion the element's nodes publish Floating with `Finding::NonConvergent`, never NaN, never a "last consistent solution" — every non-terminal node of the cluster, a path to an unmodelled rail notwithstanding (the rail's "up through the path" presentation is for a node nothing numeric reaches, not for a solve that failed). One cross-platform caveat, recorded before it can bite: an on-segment with `r_d` = 0 is stamped at the 1 µΩ floor (`g` = 1e6), so a reported branch current `g·(V_a − V_b) − i` is a catastrophic cancellation whose low bits are the elimination's rounding — deterministic per binary, but the first place an element-bearing golden blessed on macOS would diverge on ubuntu; no golden carries an element yet, and the phase that blesses the first one quantises published currents as the trace quantises states, or reports a vertical segment's current from KCL at its node. Sources stay slot → power → stuck; no HashMap on the path (D0). The incremental-vs-full test (`engine.rs:4877-4926`) is extended to terminals, Settling and PWL clusters as a hard gate. `rs422_determinism.rs` (`:88-121`, an open free-running divergence) is investigated in phase 0, before the sense→drive cascades that expose it multiply; until it is closed every new model's proving tests run in stepped mode only. Goldens: only four exist (`net_stuck_shared_node`, `nominal_analog_cluster`, `serial_levels`, `wake_ladder`); none carries Pulled ohms, caps or PWL, so every phase's gate is that all four pass **without re-blessing**. New fixtures (rc_step, i2c_bus) get goldens blessed once; CI still fails on a rewrite.

## 9. Non-goals, and the answer

Non-goals: transient/timestep SPICE or ngspice; inductor dynamics; multi-pole RC beyond the symmetric pair (one pole per block, with the finding); Newton or exponential device laws (PWL regions only); regulator current limit; pad Schmitt/hysteresis and ADC modes beyond the ROM seed; P2 current-source pull modes; isolator/receiver propagation delay; thermal and parasitics; STEP as edges; membership changes at runtime; a native `bridge_i2c`; deterministic host-PTY runs; migrating MaD's hand-wired GPIO/encoder/pulse seams (unified-drive first).

**Does it make sense?** Yes — and most of it is already the design: R1 makes a pull-up a resistor, R19 makes open-drain a released drive, R8 already specifies the closed-form RC. "A rail is more like SPICE" is right at exactly the granularity that stays cheap: a rail is a declared terminal referenced to its own ground, entering every neighbouring solve as a constant, which is what keeps every solve at m ≤ 8 and the per-edge budget intact. Your I2C example needs three things the engine lacks, none of them a solver: an impedance-aware fight rule (a 15 kΩ pull against a 30 Ω sink is not contention — today it is), P2 pad pull modes, and a pad that reads the net when it is only pulling it — the last is the one the driver actually depends on, and the reviewer found it. **Where it becomes too complex** is exactly four places, and this plan refuses each: capacitors as union-find edges (8→26-net clusters and multi-pole math), Newton or transient device laws (a timestep, convergence nondeterminism), a capacitor on a PWL node (piecewise transient simulation by the back door), and per-edge step trains. With "every component a node" taken literally — no stub tier, no facade — the price is a handful of small models nobody has needed yet (a PSRAM, an inverter, an oscillator, a regulator, a comparator, an opto), each cheaper than the stub rule that excused it, and the reward is one pipeline: a part is a node with behaviour or the board tells you which part and which value it cannot explain. Held to declared terminals, shunt-C closed forms with a stated one-pole rule, PWL regions cold-started in an ordered bounded loop, and switches as build-time unions, it is four primitives (shunt cap, PWL element, terminal, plant edge), one NetState variant, two timer targets, one projection rule, and stubs replaced by models — not a new simulator. The honest cost is the test churn in §3 and §4: those tests encoded the stubs.
## 10. The node ↔ net interface

Reviewed against the tree, against the physics of every interface on the three boards, and against IBIS 7.2, IEEE 1800/1364 strengths, IEEE 1164, SystemC-AMS, SPICE/MNA and Modelica conservative ports.

**Per instant: one message, `Drive`, three encodings, all through the same sequenced command at the producer's own instant (R1–R5).**

| Encoding | Meaning | Covers |
|---|---|---|
| `Thevenin { volts, ohms }` | a linear port; `ohms = ∞` is normalised to *released* at the slot, never ranked | push-pull pads, sinks (open-drain low = `{0 V, R_on}`, high = released), the P2's 1K5/15K/150K pull modes, rails, straps, stuck-at faults |
| `Current { amps }` | a Norton injection with no shunt: stamped as `rhs += amps`, contributes no reachability (a current source into an open loop leaves the node Floating, with a finding) | the eight NSI50010 current regulators, the P2's 1 mA/100 µA/10 µA pad modes, a regulator's input load — the two places the tree already fakes a current source with a resistor |
| `Periodic { hi, lo: Thevenin, segment: PulseSegment }` | the record's shape (`sil-unified-drive.md`): a declared compression of a Thevenin edge train with the integer `{freq_hz, since, emitted, total}` that keeps the count exact for late joiners | the step clock, forwarded verbatim by the isolator; novel by measurement (820 k edges/s), not by any standard |

No `OpenDrain`/`PushPull` kinds. Open-drain is a behaviour of the node — a sink that releases — and every kind added is an interface variant every consumer must understand; IBIS keeps its `Open_drain` model type only "for backward compatibility" and defines it as "do not use `[Pullup]`".

**Per pin, declared once on `PinDecl` and stamped by the solver, never republished** — IBIS's decomposition:

- `idle: Option<TheveninDrive>` — the power-on drive (`None` = released), which retires the release-at-attach ritual.
- `clamps` — always-stamped shunts to the pin's own supply and ground pins (IBIS `[GND Clamp]`/`[POWER Clamp]`). A pad's *driver* strength is its published Thevenin; a pad that needs a nonlinear driver curve is a PWL element part, not a pin table. Precedence stated so the two never disagree.
- `input: { v_bias, r_in }` — a sense pin's own port (IBIS `Input`): the AM26LV32's 12 kΩ to its bias is the mechanism of its open-input failsafe, a regulator's quiescent load is what holds a blocked V_IN near 0 V; without it those nodes come out of an arbitrary 1 GΩ divider.
- `capacitance_pf`, `thresholds` (`V_IL/V_IH` plus a hysteresis pair, declared relative to the pin's supply or reference pin so a brown-out scales them; JESD8C.01's 0.8/2.0 V as the net-level default), and `can_source` — the one static fact a per-instant message cannot carry. It exists for a build lint, `Finding::OpenDrainWithoutPullUp`: a pin that cannot source, on a net where no other source reaches it through less than `WEAK_DRIVE_OHMS`.
- Nonlinear devices are PWL **branches on the component** — `(pin_a, pin_b, curve, control)` — not per-pin curves to a reference: a diode is a branch between two pins, a FET channel is a D–S branch decided by V(G) − V(S), and the per-pin form is the degenerate case.

**Delivered to a sensing pin:** `Sense { volts: Option<Volts> }`, relative to the pin's declared reference — `None` means no source reaches the node, which is a fact consumers branch on (an open enable on the ISO67xx means *enabled*), not an ambiguous voltage. The digital level is the **receiver's** projection through its own thresholds and hysteresis, chosen by its last level — one compare per delivery, which is what delivery already costs. The policy for a voltage inside the dead band is declared per receiver (`HoldLast` or `Unknown`) with no crate default: `level_of → None` keeps refusing to invent a level, as today. Contention and floating stay distinguishable findings. Current into a pin is an instrument (`sense_current`), not the normal path.

**Resolution** is rule 2: sources reaching a root ranked by total ohms; a pull (≥ 1 kΩ) never contends; ≥ 10× loses with a finding; within 10× an m ≤ 2 solve publishes the divided voltage. Ordinal where Verilog's strength resolution is exact, nodal where Verilog would answer X — the 10× and 1 kΩ are embsim constants, not standard values. A root with exactly one reaching source delivers its open-circuit voltage without a solve, even to an analog sense (§12 phase 5: today every cluster carrying an analog sense solves whatever its source count).

**Sequencing, so nothing regresses:** rule 2 before the pad pull modes are mapped (today a `{3.3 V, 15 kΩ}` pull against any sink is Contention because the fight rule ignores ohms); rails as real terminals (phase 4) before the sense becomes volts-only (every supply gate reads a NaN-sourced rail's `Pulled(High)` today); ∞ Ω normalised at the slot before it can be ranked; the pulse channel folded in per `sil-unified-drive.md` steps 1–4, since today it is a second interface with its own registration, routing and un-sequenced delivery.

**What this is, in the vocabulary of other tools.** SPICE stamps every element as a Norton pair and solves KCL with a timestep; Proteus VSM keeps a strength-coded logic state per digital pin and bridges to SPICE with interface objects carrying an output resistance; Icarus and VHDL resolve by an ordinal strength table with no voltage; Renode and QEMU carry a `bool` or an `int` per line and bytes per bus, with no strength, no resistor and no conflict detection. embsim's interface is SPICE's linearisation at event instants with Proteus's ordinal shortcut where it is exact — which is why it can see the bugs the transaction-level tools cannot (a fought line, a missing pull-up, a floating input, a stretched clock) at a per-edge cost the timestep tools cannot afford.

## 11. The interface between nodes, as code

A node never sees another node. It sees its own pins: what it declared about them, the voltage the engine hands back, and the drives it publishes. Everything between two nodes is the engine's — resolution, timing, findings — so two nodes written a year apart on different boards agree by construction.

```rust
/// Declared once, at build. Static electrical facts the solver stamps and
/// the engine never asks for again. (IBIS's decomposition.)
pub struct PinDecl {
    pub number: &'static str,
    pub name: Option<&'static str>,
    pub role: PinRole,                 // Signal | PowerIn | PowerOut(Terminal) | Passive
    pub idle: Option<Thevenin>,        // the power-on drive; None = released
    pub input: Option<InputPort>,      // { v_bias, r_in }: the pin's own load
    pub clamps: &'static [Clamp],      // shunts to `supply`/`reference`, always on
    pub capacitance_pf: Option<f64>,   // to `reference`; the RC pole the engine arms
    pub thresholds: Option<Thresholds>,// { v_il, v_ih, hysteresis }, relative to `supply`
    pub reference: Option<&'static str>, // the pin its voltages are measured against
    pub supply: Option<&'static str>,
    pub can_source: bool,              // false = sink-only: the missing-pull-up lint
}

/// A nonlinear element is a branch between two of the part's pins, with an
/// optional control pin — never a per-pin curve.
pub struct Branch {
    pub a: &'static str,
    pub b: &'static str,
    pub curve: PwlCurve,               // off = GMIN; on = Vf + r_d, or R_ds(on)
    pub control: Option<(&'static str, RegionTest)>,
}

pub trait Component: Send + Sync {
    fn pins(&self) -> &[PinDecl];
    fn branches(&self) -> &[Branch] { &[] }
    fn attach(&mut self, io: ComponentNetIo) -> Result<(), AttachError>;
    fn start(&mut self) {}
}

/// The one per-instant message. Three encodings, one command, sequenced,
/// published at the producer's own instant (R1–R5).
pub enum Drive {
    Thevenin { volts: f64, ohms: f64 },        // ohms = ∞ is normalised to Released
    Current  { amps: f64 },                    // a Norton injection, no shunt
    Periodic { hi: Thevenin, lo: Thevenin, segment: PulseSegment },
}
impl PinHandle {
    pub fn drive(&self, d: Drive);              // enqueue; resolved next pass
    pub fn release(&self);                      // Thevenin { ohms: ∞ }
    pub fn sense_current(&self) -> Amps;        // an instrument; escalates its cluster
}

/// What a sensing pin is handed: the node voltage relative to the pin's
/// declared reference, or nothing if no source reaches the node.
pub struct Sense { pub volts: Option<f64>, pub at_ns: u64 }
impl Sense {
    /// The receiver's own projection: its thresholds, its hysteresis, its last level.
    pub fn level(&self, thresholds: &Thresholds, last: Option<Level>) -> Option<Level>;
}
impl ComponentNetIo {
    pub fn pin(&self, id: &str) -> Result<PinHandle, AttachError>;
    pub fn on_sense(&self, id: &str, f: impl Fn(Sense) + Send + 'static) -> Result<(), AttachError>;
    pub fn on_branch(&self, id: &str, f: impl Fn(Amps) + Send + 'static) -> Result<(), AttachError>;
    pub fn on_wake_ns(&self, f: impl Fn(u64) + Send + 'static);
    pub fn schedule_at_ns(&self, at_ns: u64);
}
```

**The contract, six lines.**

1. A node publishes only what it drives on its own pin, at the instant it drove it, and reads only the voltage the engine hands it. It never publishes the net's result, never reads by differencing timestamps, and retracts by publishing again (R3–R5).
2. A node never commits state ahead of virtual time; it schedules a wake and acts when the engine arrives (R1). The engine never advances past an undelivered publish (R2).
3. Everything static is declared, everything dynamic is a `Drive`. A pin's strength is its published Thevenin; its clamps, capacitance, thresholds, input load and sourcing capability are declarations; a nonlinear device is a `Branch` on the component.
4. The engine owns resolution: the impedance ranking, the nodal solve, the RC crossing instants, the region loop, contention and floating as findings. No node re-implements any of it, and no node can be given a shortcut around it.
5. A rail is a node too: a `PowerOut` terminal driving a `Thevenin` from its own ground pin, with the same message as a pad.
6. There is no second channel. The pulse train is `Drive::Periodic`, routed and sequenced like every other drive, kept only because 820 000 edges a second was measured; a node that consumes one integrates the segment itself.

**What changes from today's trait**, in one column: `PinKind` (7 variants deciding electrical defaults) becomes `PinRole` plus declarations; `NetState` (5 variants, one global threshold) becomes `Sense { volts: Option }` plus the receiver's projection; `set_drive(Option<TheveninDrive>)` becomes `drive(Drive)` with `Current` and `Periodic`; `StreamRole`/`pulse_tx`/`on_pulse` fold into `Drive::Periodic`; `Component` gains `branches()`. The `Component`/`attach`/`start` shape and the wake scheduling are unchanged — the QEMU P2 node, the flash, the card and the ADC front end port by editing their tables, not their logic.
